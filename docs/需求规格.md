# 热点监控系统：需求规格

## 背景与目标

用户希望在无需反复手动搜索的情况下，尽早获知指定关键词的真实新动态，并定期发现指定领域内的热点。典型场景包括 AI 大模型发布和 AI 编程领域的新变化。

本文件整理自仓库根目录的 `需求.md` 和后续沟通。第一版为本机运行的单用户产品；本机服务运行期间持续监控。

## 功能需求

1. 用户能创建、编辑、启停和删除监控项。监控项分为“关键词提醒”和“领域发现”。
2. 关键词提醒定期搜索新内容。只有内容确实相关、证据达到核实标准且未通知过时，才触发提醒。
3. 领域发现定期收集主题相关的新内容，按新颖度、热度和证据质量排序，在网页展示。
4. 内容至少来自网页搜索、X 信息和公开新闻或官方信息源，不能只依赖单一来源。网页搜索不使用付费搜索 API，通过公开搜索网址低频获取；X 通过 twitterapi.io 的 API 获取。
5. 利用 OpenRouter 接入 AI，识别内容相关性、假冒或误传线索，生成中文摘要、判断理由和可信度状态。每项结果保留原始链接及来源。
6. 已核实的关键词事件通过网页内提醒及邮件提醒。网页可查看历史提醒、待核实结果和采集状态。
7. 页面兼容桌面和手机，视觉设计具有鲜明识别度。
8. 网页版功能正常、完成测试后，再封装 Agent Skills 供其他 AI 使用相同监控能力。

## 第一版默认规则

- 关键词每 5 分钟检查一次，领域每 30 分钟检查一次；界面可调整周期。
- “第一时间”指下一轮采集、AI 判读和证据核实后尽快通知，并非毫秒级实时推送。
- 由用户在本机配置的官方 RSS 源，其最近三天发布且链接仍指向同一站点的原始公告，或至少两个独立来源（其中至少一个不是 X 帖文）相互印证，才将事件标记为“已核实”。仅有单一非官方来源时标记“待核实”。明显不相关或疑似冒名内容标记“疑似误传”。
- AI 不具有事实保证能力，最终状态还受来源与证据规则约束。来源无法访问或 AI 服务不可用时，不将候选内容自动判为已核实。
- 相同事件去重，不重复发送邮件。通知失败保留记录与错误信息，便于重试和排查。

## 验收标准

1. 在本机启动服务后，可在手机宽度和桌面宽度正常使用网页。
2. 可新增关键词与领域监控项，并在页面看到采集状态、结果及原文链接。
3. 多来源采集可分别工作；某一来源失败不会阻断其他来源。
4. OpenRouter 有有效密钥时，实际调用完成结构化判读；无效或缺失密钥时，网页明确显示配置或调用错误，不伪称 AI 已完成核实。
5. twitterapi.io 有有效密钥时，能够取得 X 搜索结果；无效或缺失密钥时明确显示状态。
6. 对已核实且首次出现的关键词事件生成网页提醒；SMTP 配置有效时发送邮件，并防止重复发送。
7. 自动测试覆盖采集解析、去重、核实门槛、API 主要流程和通知逻辑；提供可重复执行的测试命令。
8. 网页版达到上述标准后，再开发和测试 Agent Skills。

## 配置与边界

OpenRouter、twitterapi.io 和 SMTP 凭据由用户在本机环境配置，不写入仓库。第三方服务可能产生费用；外部来源可用性、网络延迟及本机开机状态会影响通知时效。首版不包含多用户账号、云端部署或全网覆盖承诺。
