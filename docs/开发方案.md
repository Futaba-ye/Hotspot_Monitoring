# 热点监控系统：开发方案

## 实施顺序

1. 完成网页版：本地数据库、采集器、AI 判读、通知、界面及配置说明。
2. 对网页版执行单元测试和端到端测试，核对实际第三方接口；修复问题。
3. 网页版确认可用后，封装 Agent Skills 并测试。
4. 提供运行及验收说明，请用户验收。

## 技术结构

- 前端：React + Vite。使用深色“热点情报台”设计，重点展示扫描状态、时间线、证据与可信度；手机端重新布局。
- 后端：FastAPI。提供监控项、事件、提醒、状态和手动扫描 API；通过应用生命周期启动单进程调度循环。
- 存储：SQLite。保存监控项、采集原文、归并事件、AI 判读、通知和任务状态。
- 采集：网页搜索结果页的低频抓取、公开新闻与官方 RSS、twitterapi.io 的 X 搜索。各来源独立执行；设置超时、限速、失败退避与来源标识。
- AI：后端通过 OpenRouter Chat Completions API 调用可配置模型，要求 JSON Schema 结构化输出；结合确定性来源规则形成最终可信度状态。
- 通知：网页内提醒通过轮询获取；邮件通过 SMTP 发送并记录结果。
- 凭据：由 `.env` 读取，只在后端使用；仓库仅提供 `.env.example`。

## 主要数据流程

监控项 → 各来源采集 → URL 与内容去重 → AI 相关性和误传线索判读 → 同事件归并及来源核实 → 保存事件 → 满足关键词通知条件时创建提醒并发送邮件 → 网页展示。

领域发现使用同一数据流，但默认只展示热点，不发送邮件。网页展示每个事件的原文链接、采集时间、证据和判读理由。搜索结果中的标题和摘要只是线索，无法获取原文时降低可信度。

## 接口与版本核对

2026-10-28 已使用 MCP 搜索服务读取以下官方文档，开发中以这些接口为准：

- [twitterapi.io Advanced Search](https://docs.twitterapi.io/api-reference/endpoint/tweet_advanced_search)：`GET /twitter/tweet/advanced_search`，`X-API-Key` 请求头，`query` 与 `queryType=Latest`，结果为 `tweets`。
- [twitterapi.io Rate limits](https://docs.twitterapi.io/rate-limits)：新账号未充值时每 5 秒 1 次请求；收到 429 时退避。按结果计费，因此限制单轮查询数量。
- [OpenRouter Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request)：`POST /api/v1/chat/completions`，Bearer 密钥。
- [OpenRouter Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs)：通过 `response_format.type=json_schema` 请求结构化 JSON；仅选择支持此能力的模型端点。
- [FastAPI Lifespan](https://fastapi.tiangolo.com/advanced/events/)：通过 `lifespan` 管理服务启动和关闭时的后台任务。
- [Vite 入门](https://vite.dev/guide/)：使用当前稳定版工具链构建 React 页面；本机安装并构建时验证版本兼容性。
- [NVIDIA Nemotron 3.5 Super VL 免费模型](https://openrouter.ai/nvidia/nemotron-3.5-super-vl:free)：当前默认模型支持 JSON Schema 结构化输出；通过 `provider.require_parameters=true` 约束路由。免费额度有每日上限，持续高频监控可切换到支持 JSON Schema 的付费模型。
- [OpenAI 官方新闻 RSS](https://openai.com/news/rss.xml)：默认的官方原始信息源，只处理最近三天发布的条目；可通过 `OFFICIAL_RSS_URLS` 增加其他官方 RSS。

第三方接口在验收前再次核对实际请求和响应。依赖安装时固定兼容版本，避免将 APScheduler 3.x 和 4.x 接口混用。调度器第一版直接使用 Python 异步循环，减少版本耦合。

实际安装版本：FastAPI 0.162.0、httpx 0.28.1、React 19.3.1、Vite 8.3.5。Python 3.13.3 与 Node.js 24.14.0 下已完成构建和自动测试。

## 验证方式

- 通过模拟来源响应测试解析、失败退避、跨来源归并和通知幂等性。
- 用本机 API 测试新增监控项、手动扫描、结果查询与配置状态。
- 在浏览器检查桌面和移动端布局、交互、空状态及错误状态。
- 有真实密钥时做 OpenRouter、X 和 SMTP 的连通测试；未配置密钥时清楚标识未验证项。
